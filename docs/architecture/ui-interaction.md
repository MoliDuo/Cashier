# 编辑交互约定

## 适用范围

设置页，以及任何"列出一批对象、就地改其中一个"的界面（分账、分类、API 密钥、登录邮箱）。
约定的是**改动放在哪里发生**和**什么时候写库**，不约定视觉样式、文案和数据流。

问题来自同一张卡片里自相矛盾：分账的排序和时区点一下就生效，偏偏名字要开一个弹窗；
改名入口在分类里是铅笔图标，在分账里是一个写着"重命名"的文字按钮。

## 四条规则

### 1. 单字段就地改，立即生效

改一个**已存在**对象的、**行里已经看得见**的**单个**字段，就在那一行改，回车即写库，
不进编辑模式、不开弹窗。写库失败由 toast 说明原因，输入保留在编辑态等待修正。

开关、下拉这类选完即定的控件改完就写库；长文本在离开输入框时写库。写库期间同一分区的控件禁用，
所以每次保存都基于上一次写下的版本。设置在别处改过时，这次写库被拒，页面载入最新值，读者重新改。

适用：分账名称、分账时区、API 密钥所属分账、外观、记账规则（折叠、AI 语言、提示词、币种）。

**不为这种改动开弹窗。** 弹窗遮住了读者刚才在看的那一行，为一个字段付这个代价不划算。

### 2. 成组字段，编辑模式 + 分区级保存 / 取消

一组**互相约束、必须一起校验**的字段，或者会**改动列表结构**（增删、排序）的一批改动，
用一次编辑会话承载：进入模式 → 就地改 → 分区标题行或底部的保存 / 取消。
未保存的修改存成草稿（`src/lib/drafts.ts`），离开时不确认，下次打开时恢复并提示"有未保存的修改 · 放弃"。
只有主动点"取消编辑"时才确认放弃。

分组的依据是写库本身是一个事务，而不是字段之间的校验：能拆成单字段写的（主币种切换时顺带把它加进
常用币种），走规则 1。编辑期间服务端版本变了，草稿不能覆盖，界面提示"分类已在别处更改"并提供载入最新。

适用：分类管理（排序 / 增删 / 改名一起提交，带修订冲突检测）、分类预设切换、源单据详情的编辑模式。

### 3. 弹窗只留给四种事

| 用途                   | 例子                      |
| ---------------------- | ------------------------- |
| 新建尚不存在的对象     | 新增分账、新建 API 密钥   |
| 多步流程               | 添加登录邮箱的验证码      |
| 一次性不可再得的信息   | 新建密钥后展示的 token    |
| 行内放不下的多字段编辑 | 分类的 图标 + 名称 + 描述 |

"行内放不下"以**三个及以上字段**或**需要图标选择器 / 长文本**为界。两个字段放得下，走规则 1。

### 4. 破坏性动作一律确认弹窗

删除、归档、退出登录、放弃未保存草稿，全部走 `ConfirmDialog`，`variant="destructive"`。
这条不因为改动小而豁免。

## 现状归属

| 位置     | 操作                        | 形态            | 依据   |
| -------- | --------------------------- | --------------- | ------ |
| 分账     | 名称、时区、排序            | 就地，立即生效  | 规则 1 |
| 分账     | 新增                        | 弹窗            | 规则 3 |
| 分账     | 归档、删除                  | 确认弹窗        | 规则 4 |
| 分类     | 排序、增删、改名            | 管理模式 + 保存 | 规则 2 |
| 分类     | 图标 + 名称 + 描述          | 弹窗            | 规则 3 |
| 外观     | 主题                        | 就地，立即生效  | 规则 1 |
| 记账规则 | 折叠、AI 语言、提示词、币种 | 就地，立即生效  | 规则 1 |
| API 密钥 | 所属分账                    | 就地，立即生效  | 规则 1 |
| API 密钥 | 新建、token 展示            | 弹窗            | 规则 3 |
| API 密钥 | 删除                        | 确认弹窗        | 规则 4 |
| 登录邮箱 | 添加（验证码）              | 弹窗            | 规则 3 |
| 登录邮箱 | 移除                        | 确认弹窗        | 规则 4 |
| 账户     | 退出登录                    | 确认弹窗        | 规则 4 |

## 视觉与可访问性约定

编辑入口一律是铅笔图标按钮（`Pencil`、`variant="ghost"`、`size="icon-sm"`），不用文字按钮；
图标按钮必须带 `aria-label` 和 `title`，并带上对象名字，这样屏幕阅读器在一列同样的按钮里
听得出改的是哪一行。

行内动作按钮组顺序固定为 **上移 / 下移 / 编辑 / 归档 / 删除**，归档和删除用
`text-muted-foreground hover:text-danger`。

就地编辑态里，动作组换成勾（保存）和叉（取消），Enter 等同于勾、Esc 等同于叉，
输入框自动聚焦，写库期间输入框和两个按钮一起禁用。

## 新增设置项时

按规则 1 → 2 → 3 的顺序问：这是一个字段吗？它和别的字段一起校验吗？它需要弹窗的四种理由之一吗？
前两问任意一个答"是"就到此为止，不要再往弹窗走。
