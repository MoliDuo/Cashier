# 从双人账本升级到单账户 + 分账

`0048_books_and_single_account.sql` 把"两个成员"改成"一个账户 + 分账（books）"：
每个用户行不再自带邮箱、昵称、性别和时区，记录的分账由 `book_id` 表示，
API 密钥绑定到分账，登录邮箱存放在 `login_emails`。

这是一次不可逆迁移：梁梁的用户行、`users.email`、`users.nickname`、
`users.gender`、`users.time_zone` 都会被删除。升级前务必先备份并演练。

## 迁移做了什么

1. **守卫。** 迁移要求：只有一个存活账本；`xiangyu.moe.ac@gmail.com` 与
   `liangyilinhuaxue@163.com` 两个存活用户都存在；没有第三个持有数据的存活账户；
   并且没有 `source_documents` / `service_credentials` 行落在存活账本之外或归属于
   其他账户（常见于旧合并遗留的软删除账本）。任何一条不满足都会在写入任何 DDL
   之前报错中止，错误信息会给出具体是哪张表、多少行。
2. **建 `books` 表**，并写入三行：`哞哞的`（沿用哞哞的用户 UUID 与其时区，排序 1）、
   `梁梁的`（沿用梁梁的用户 UUID 与其时区，排序 2）、`共同支出`（新 ID，无时区，
   排序 3，曾标记 `is_default = true`——该标记随后由 0049 移除，总账不再需要
   默认分账）。
3. **`source_documents.attributed_user_id` 改名为 `book_id`。** 因为两个个人分账直接
   沿用了用户 UUID，这次改名就是回填：每条记录都仍然属于原来那个人。
   同时删除 `created_by_user_id`（不再记录"谁录入的"），并把外键改成分账的复合键。
4. **`service_credentials.attributed_user_id` 改名为 `book_id`。** 现有密钥继续可用：
   梁梁的密钥写入`梁梁的`，哞哞的写入`哞哞的`。
5. **建 `login_emails`**，把两个邮箱都指向哞哞那一行（它成为账户本身）。哞哞的密码
   与偏好保留；梁梁的密码不再存在，因为现在只有一个密码。`auth_version` 加一，
   所有人被登出一次。删除梁梁那一行之前，先把 `ledgers.user_id` 指向她的行改挂到
   哞哞名下——该外键是 `ON DELETE CASCADE`，否则删除会连带删掉她的账本（以及
   里面的记录）。删除后再断言存活账本与 `source_documents` 行数未变，否则中止。
6. **删除旧列**：`users` 的 `email`、`nickname`、`gender`、`time_zone`，
   以及 `ledgers` 上限制"一人一个账本"的 `uniq_ledgers_user_id`。
7. **空库也走同一条迁移。** 如果数据库里没有存活用户也没有存活账本，迁移只做结构变更，
   数据部分整体跳过，随后由 `/setup` 向导创建账户、账本和分账。

## 升级步骤

0. **前置条件：数据库必须已经是"一个账本"。** 0048 的守卫要求存活账本恰好一个
   （见下节第 1 条）。这条迁移只负责"双人账本 → 单账户"这一步；把多用户数据库
   收敛成双人账本的是更早的双人合并工具（`scripts/migrate-couple-ledger.ts`、
   `scripts/prune-non-couple-users.ts`），它们已随本次改造删除。因此如果拿到的备份
   里仍有多个存活账本（例如 2026-09-17 那份多用户原始转储是 6 个），
   `npm run db:migrate` 会在写入任何 DDL 之前中止并报
   `0048 requires exactly one live ledger, found 6`。请改用合并后的快照
   （如 `cashier_couple_rehearsal`）演练，或先在旧版本上完成双人合并。
1. 备份 PostgreSQL（自定义格式完整转储），并另外备份 S3/R2/MinIO 存储桶。
   存储桶里是原始票据图片，迁移不触碰它们。
2. 在**本地副本**上先演练：恢复一份转储到单独的数据库，运行 `npm run db:migrate`，
   再按下面的检查清单核对。
3. 在生产上停止应用实例，运行 `npm run db:migrate`，确认成功后再启动新版本。
   迁移的全部 DDL 与数据变更在同一个事务里；守卫失败时数据库保持原样。
4. 删除部署环境中已失效的 `COUPLE_*` 变量。它们不再被读取。
5. 迁移后所有人需要重新登录一次（`auth_version` 已加一）。

## 演练检查清单

在本地副本上核对（2026-09-18 已在合并后的生产快照上按此清单核对通过：1547 条记录 =
哞哞的 1229 + 梁梁的 318，收支合计 102743.90 与迁移前逐项相等，3 个密钥各归其位，
软删除账本未丢失）：

- 迁移前按 `attributed_user_id` 统计的记录条数，等于迁移后按 `book_id` 的条数，
  并且两个个人分账的数字与原来两个人的数字一致。
- `ledger_entries` 的条数与金额合计逐项不变。
- API 密钥条数不变，每个现有密钥仍然能通过鉴权，并且上传落到正确的分账。
- 两个邮箱都能用验证码登录。
- `xiangyu.moe.ac@gmail.com` + 原密码可以登录；`liangyilinhuaxue@163.com` + 同一个
  密码也可以登录（现在共用一个密码）。

## 回滚

没有回滚脚本。唯一可靠的恢复方式是恢复升级前的转储，再切回旧版本镜像。
因此请务必在动生产之前完成演练。
